# 归档索引与随机访问（从 0 实现）

起始环境里没有代码：只有这份说明和 `samples/` 下的归档与期望结果，实现要新写。

## 1. 范围

**做什么**：实现一个只读的归档索引与随机读取工具（库 + 命令行 + 一个生成的页面）。

- 解析头部与条目表，扫出每个条目的数据位置，写出可复用的索引；
- 按索引单独读出指定条目：读一条不许解压整包，也不许碰别的条目的压缩数据；
- 对坏包报出问题类型，并定位到条目与偏移；
- 生成单文件 `archive.html`：列出条目表，点一条显示它的偏移、压缩前后大小、本次读入字节数与读取耗时，数值全部取自引擎；
- 交付 Python 3.13 + 标准库（压缩交给 `zlib`，不要自己实现压缩算法），测试用 `unittest`，无构建步骤、无第三方依赖、页面不引 CDN。

**不做**：写入、追加、删除、重新打包、把归档解压到目录、加密与校验修复、并发与多进程、网络请求、图形界面、与真实压缩工具互操作。

## 2. 口径与公式

- 整数一律小端无符号；名字是 UTF-8，1–1024 字节，不含控制字符（含 Tab 与换行）。
- `crc32` 取 `zlib.crc32` 的结果，输出成 8 位小写十六进制。
- 条目内容按 65536 字节切段：段数 `k = ceil(原始大小 / 65536)`，末段是余数，其余段都是 65536 字节。
- 每段独立压缩成 zlib 流（RFC1950）；`数据偏移` 是条目第一段段头的位置，`跨度` 从它算到该条目末段段体结束，
  即 `Σ(4 + 该段压缩体字节数)`。
- 三条上界：索引体积 ≤ `1024 + 48 × 条目数 + 16 × 段总数 + 名字总字节数`；
  建索引读入 ≤ `32 + 条目表字节数 + 4 × 段总数 + 4096`；单条读入 ≤ `该条目跨度 + 1024`。单位都是字节。
- 「读入字节数」只统计引擎从归档文件对象取回的字节数，不含索引与输出文件。

## 3. 归档布局与数据结构

字节布局：`头部 32 字节` + `条目表` + `数据区（分段压缩流）`。

**头部**（小端，共 32 字节）

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 4 | 魔数 `ARCK` |
| 4 | 2 | 版本，固定 1 |
| 6 | 2 | 保留，固定 0 |
| 8 | 4 | 条目数 n |
| 12 | 8 | 条目表偏移 T |
| 20 | 4 | 条目表字节数 S |
| 24 | 8 | 文件总长 L，必须等于实际字节数 |

**条目表**：T 起 S 字节，n 条变长记录顺序排列；第 i 条是 `u16 名字字节数 m` + `m 字节名字` +
`u64 原始大小` + `u32 crc32(原始内容)`。表里不含偏移与压缩长度。

**数据区**：T+S 起，按条目表顺序一条接一条；每段是 `u32 压缩长度 c` + `c 字节 zlib 流`。

**解析顺序**：读头部 → 校验魔数、版本、L 与实际字节数 → 校验条目表区间 → 逐条解析记录 →
从数据区起点顺序扫段头（按 c 跳过段体，不算读入），直到所有条目的段都数完。

**索引**：`index` 的产物至少要能按名字找到条目的数据偏移、跨度、原始大小、crc32 与段数，
并判断是否与这份归档配套（例如记下 L）；索引里不许存条目内容，建索引不读段体。

## 4. 输入输出与文件格式

命令行在仓库根目录执行：

- `python -m arcidx index <归档> <索引>`：扫一遍归档写索引，stdout 一行 `index	条目数	段总数	索引字节数	读入字节数	耗时毫秒`。
- `python -m arcidx list <归档> <索引>`：打印条目表。
- `python -m arcidx read <归档> <索引> <条目名> <输出文件>`：随机读一条，写出原始内容。
- `python -m arcidx html <归档> <索引> <输出.html>`：生成单文件页面。
- `python -m arcidx check <归档>`：诊断坏包。

输出与接口口径：

- `list`：每条目一行、7 列 TSV，顺序同条目表：`序号(从0) 名字 数据偏移 跨度 原始大小 crc32 段数`；
  与 `samples/expected/*.entries.tsv` 逐字节相同（LF 结尾，Windows 上也显式写 `\n`）。
- `read`：stdout 一行 TSV：`read 名字 数据偏移 跨度 原始大小 读入字节数 耗时毫秒`（耗时三位小数）；
  内容要用表里的 crc32 校验，不符按非 0 退出。
- `html`：单文件、数据内联、双击即开、不发请求；生成时对每个条目各做一次随机读，
  把偏移、压缩前后大小、本次读入字节数与耗时写进页面，点击条目显示这些值。
- 库入口：`arcidx.open_archive(归档, 索引)` 给对象，`entries()` 是条目表（字段同 `list`），
  `read(名字)` 给 `bytes`，最近一次统计在 `last_read`；索引缺失或不配套按用法错误退出（码 2）。

**坏包与诊断**：`check` 按第 3 节的顺序走，发现问题打印一行四列 TSV `代码 条目 偏移 说明`
（没有的列写 `-`）；无问题时不输出、退出码 0，有问题退出码 1。

| 代码 | 条目 | 偏移 | 说明 |
| --- | --- | --- | --- |
| `LENGTH_MISMATCH` | `-` | 头部声明的总长 L | `actual=<实际字节数>` |
| `TABLE_RANGE` | `-` | 条目表偏移 T | `size=<表长 S> limit=<声明总长>` |
| `STREAM_TRUNCATED` | 条目名 | 出问题那段的段头偏移 | `segment=<段序号,从0> need=<该段字节数> have=<剩余字节数>` |

头部不足 32 字节、魔数或版本不符也报 `LENGTH_MISMATCH`，偏移列写 `-`；段头读不满时 `need=4`。

## 5. 性能与验收口径

- 规模：`samples/archives/many-small.arc` 是 500 个条目的包；真实包可能到 2 GB / 几百个条目，
  建索引与读取都不许把整包读进内存，峰值内存 ≤ 128 MiB。
- 预算（Windows + Python 3.13、单进程）：建索引 ≤ 2 秒；单条随机读 ≤ 20 毫秒（含查索引、解压与校验，
  不含解释器启动）；生成页面 ≤ 10 秒。
- 确定性：同一归档跑两遍，索引文件、`list` 输出与读取内容逐字节相同；页面除耗时数值外相同（不掺时间戳与随机数）。
- 验收：① 4 个包的 `entries.tsv` 与 `list` 输出逐字节相同；② `reads.tsv` 的条目读出来 crc32、sha256
  对上且读入 ≤ 跨度 + 1024；③ 3 个坏包的 `check.tsv` 与 `check` 输出逐字节相同、退出码 1；
  ④ 索引 ≤ `limits.tsv` 上界且两次一致；⑤ `python -m unittest discover` 通过、只用标准库；
  ⑥ `archive.html` 双击可开，点开条目显示的偏移、压缩前后大小、读入字节数、耗时同引擎输出一致。

## 6. 样例说明

`samples/archives/*.arc` 与 `samples/expected/<包名>.entries.tsv`、`<包名>.reads.tsv` 一一对应；`samples/broken/*.arc` 与同名 `.check.tsv` 一一对应。

| 归档 | 条目数 | 归档字节 | 原始字节 | 段数 | 覆盖 |
| --- | --- | --- | --- | --- | --- |
| `many-small.arc` | 500 | 887975 | 2815578 | 510 | 条目多而小，带目录层级的名字 |
| `few-large.arc` | 5 | 1049783 | 1900544 | 29 | 条目少而大，最大一条 786432 字节、12 段 |
| `skewed.arc` | 8 | 142735 | 524288 | 8 | 压缩率差异极大：最低约 1.0，最高约 745 |
| `long-names.arc` | 12 | 62870 | 118950 | 12 | 名字 130–1024 字节，含中文 |

`samples/expected/limits.tsv` 给出每个包的条目数、段总数、名字总字节数与两条上界；
`samples/notes.md` 是现场记录，只描述现象，口径以本说明为准。
